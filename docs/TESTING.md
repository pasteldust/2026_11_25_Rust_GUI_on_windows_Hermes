# テスト方針

## 三層で確かめる

| 層 | 対象 | 実行 | 場所 |
| --- | --- | --- | --- |
| Unit | ドメイン（画素・レイヤー・文書）、描画のラスタライズ、履歴、ファイル形式の断片 | `cargo test` | 各クレートの `src/**` 内 `#[cfg(test)]` と `tests/` |
| Integration | GUI を除く全コンポーネントの組み合わせ（読込→描画→保存→再読込→Undo→Redo） | `cargo test` | `crates/*/tests/` と `paint-app` の ViewModel テスト |
| E2E | Windows 上での実際の exe（起動・描画・保存・再読込・Undo・Redo） | GitHub Actions `E2E (windows-latest)` / 手元の `--self-test` | `crates/paint-app/src/self_test.rs` |

## なぜ GUI を外してテストするのか

egui のウィンドウを開かないと検証できない作りにすると、CI でも手元でも自動テストが書けない。
そこで **描画のロジックは `paint-engine`、操作の組み立ては ViewModel** に寄せ、
GUI（`paint-app/src/app.rs`）は「ViewModel の状態を描き、入力を渡すだけ」に徹する。
結果として、線が途切れないこと・太さが効くこと・Undo で元に戻ることは、
すべてヘッドレスのテストで保証できる。

## E2E（Windows）

`--self-test <出力先>` は GUI を開かずに次を実行し、結果を JSON で出力する。

1. 新しい文書を作る（起動に相当）
2. 下絵画像を読み込む
3. ペン・直線・点・消しゴムで描く（描画）
4. `.paint` に保存する（保存）
5. 保存したファイルを読み直し、画素が一致することを確認する（再読込）
6. Undo で元に戻り、Redo で復元することを確認する（Undo / Redo）
7. PNG に書き出し、透過が保たれていることを確認する

いずれかが失敗したら終了コード 1 を返すので、CI はそれをそのまま検出できる。
GUI ランナーの無い CI 環境では実際のウィンドウ表示は確認できないため、
**「起動」は exe の自己テスト起動（初期化〜描画〜保存の完走）で代替**している。
ウィンドウ表示そのものは手元（Windows）での手動確認項目とする。

## テストを書くときの約束

- テスト用の画像ファイルはリポジトリに置かず、テスト中に生成する。
- 失敗したときに原因が分かるよう、`assert` には実際の値（座標・色・件数）を添える。
- 乱数は使わない（並び順や値が揺れると CI が不安定になる）。
- 壊れた入力（切り詰めファイル、巨大な長さ、範囲外の座標）は、
  **エラーを返すこと**を必ずテストする（panic しない）。
